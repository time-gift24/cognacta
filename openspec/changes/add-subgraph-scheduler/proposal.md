# 静态 Graph 与统一 Scheduler 的子图调用规格

状态：已完成需求讨论，待实施。本文记录本次拟议变更，不表示当前代码已经提供这些能力。

## Problem Statement

当前图内核能够执行静态节点和 template 动态实例，但缺少统一的图调用契约。所有入口收到同一组外部值，最终输出汇总多个终点或叶子节点，调用方需要理解图的内部节点才能取得业务结果。

把一张图作为另一张图中某个节点的执行内容时，需要保持普通节点的实例化与调度规则，同时隔离父子的运行状态。调用方应当只关心显式输入、最终结果和稳定的错误类别，并能自行决定重试、降级或传播失败。嵌套调用还需要父子身份、深度限制和观测关联，避免无限相互调用。

调度能力应归属于 Scheduler。为每张子图再创建绑定图与调度器的调用包装，会增加不必要的对象和转发层，也模糊 Graph 作为静态定义的职责。

## Solution

Graph 声明自己的 State 类型、唯一业务输出类型和公共资源类型，是可复用的静态定义。每次执行创建独立 Run；作为子图使用时，它仍由父图中的普通 NodeInstance 发起调用，沿用相同的 template、Deliver、join 和 wave 规则。

Scheduler 成为调度 trait，call 直接接收目标、按入口分配的输入和父调用上下文。现有具体调度实现命名为 LocalScheduler。本地实现既能返回完整 Run 供宿主检查，也能通过 call 仅向父节点交付最终业务结果的 Arc 或统一错误。一个本地调度实例可以执行多张图，不增加目标绑定包装。

每张图有唯一显式返回节点。其结果只有在整图成功完成后才交付。父子通过输入和结果通信，各自创建 State；公共资源通过 Context 中显式提供的强类型资源对象共享。异步 State 初始化、默认初始化、深度预算和观测都纳入统一调用过程。

## User Stories

1. As a 图定义者, I want Graph 只保存静态执行定义, so that 同一张图能够重复运行和嵌套使用。
2. As a 图定义者, I want 声明明确的业务输出类型, so that 调用方无需解析内部节点输出集合。
3. As a 图定义者, I want 显式指定唯一返回节点, so that 图的返回契约不依赖叶子节点布局。
4. As a 图定义者, I want 多个分支在图内汇聚成最终结果, so that 对外只暴露一个稳定的业务返回。
5. As a 图定义者, I want 用单元类型表达成功但无业务返回, so that 这种成功与缺失返回值可被区分。
6. As a 调用方, I want 等整图成功完成后才收到结果, so that 返回节点提前成功不会隐藏其他分支的失败。
7. As a 多入口图调用方, I want 按入口分别提供输入, so that 不同入口可以接收不同类型及内容的数据。
8. As a 图定义者, I want 默认从零入度节点确定入口并保留显式入口能力, so that 既有有入度入口语义仍然可用。
9. As a 调用方, I want 启动前检查输入是否恰好覆盖全部入口, so that 缺失和多余的输入键不会在执行中被静默忽略。
10. As a 入口节点作者, I want 接受显式空输入并自行决定是否需要数据, so that 框架不会强制所有入口携带业务值。
11. As a 节点作者, I want 保留类型化输入读取及其错误, so that 输入不满足节点能力时能够明确失败。
12. As a 父节点作者, I want 子图只接收显式选择的输入, so that 父 Run 的 State 和内部输入来源不会自动传入子图。
13. As a 图定义者, I want 父子使用不同的 State 类型, so that 每张图可以独立设计内部状态。
14. As a 图定义者, I want 每次新调用创建独立的初始 State, so that 重复执行和重试不会接续失败调用的运行状态。
15. As a 图定义者, I want 为图注册异步 State 初始化函数, so that 初始化可以使用本次输入和显式资源。
16. As a 图定义者, I want 未注册初始化函数时使用 Default, so that 简单状态不需要额外初始化代码。
17. As a State 作者, I want 自定义初始化时不被要求实现 Default 或 Clone, so that 状态类型只承担实际需要的约束。
18. As a State 作者, I want 初始化策略由图选择而不强制进入 State trait, so that 同一 State 类型可以服务不同初始化需求。
19. As a 节点作者, I want 普通节点与子图都交付业务值的 Arc, so that 结果能直接转发且不重复包装或要求业务值可克隆。
20. As a 父节点作者, I want 通过构造注入 Scheduler trait 的实现并显式指定调用目标, so that 调度依赖可以替换而无需绑定调用包装。
21. As a 图定义者, I want 子图节点和其他节点遵循同一套 template 规则, so that 静态节点及 Deliver 实例没有两套生命周期模型。
22. As a 运行宿主, I want 复用同一个 LocalScheduler, so that 根图和子图使用一致的本地调度行为。
23. As a 运行宿主, I want 并发名额按 Run 分别计算, so that 等待子图的父节点不会占满子图的执行名额。
24. As a 父节点作者, I want 得到稳定的调用错误类别及可诊断的 source, so that 可以决定如何处理失败而不解析子图内部状态或错误文本。
25. As a 父节点作者, I want 每次重试创建新的子 Run, so that 重试的身份、State 和执行记录独立且可以关联观测。
26. As a 父节点作者, I want 明确接受失败后正常返回 Outcome, so that 丢弃或降级按 Completed 参与后续调度而不是被标记为 Skipped。
27. As a 父节点作者, I want 未处理的错误继续传播, so that 子调用不会静默吞掉失败。
28. As a 运行宿主, I want 根 Run 决定整条调用链的最大深度, so that 图之间的递归或相互调用有一致的停止边界。
29. As a 运行宿主, I want 子身份、父关联和深度自动派生, so that 业务节点无需手工填写调用链字段。
30. As a 运行宿主, I want 检查本地执行的完整 Run, so that 可以查看状态、节点记录、错误与类型化最终输出。
31. As a 应用组装者, I want 使用强类型资源对象并通过 Arc 显式提供, so that 节点直接访问已知资源而不依赖动态服务查找容器。
32. As a 应用组装者, I want 无资源时使用单元类型, so that 简单图不必定义空资源接口或标记 trait。
33. As a 运行维护者, I want 将开始、完成和失败关联到父 Run 与父 NodeKey, so that 能定位具体一次嵌套调用及其初始化或执行阶段。
34. As a 运行维护者, I want 观测不泄漏输入、输出、State 和凭据, so that 本地与远程遥测都遵循安全字段约定。
35. As a 外部 agent 接入者, I want 调度 trait 不强制要求本地 Graph 或完整 Run, so that 后续可以接入其他目标的执行实现。
36. As a 测试作者, I want 在公开调度边界验证行为并注入小型 fake, so that 测试不依赖内部算法或通用 mock 框架。

## Implementation Decisions

1. **范围与职责。** 本次修改现有 core 的图定义、输入、节点上下文、结果、Run、调度及错误契约，并适配已有 CLI dev 样例和公开 API 验收。保持现有 crate 边界，不增加产品运行 crate、数据库 schema 或迁移。State 的归并职责和 derive 语义不变。
2. **调度抽象。** Scheduler trait 对调用目标类型、业务输出类型和资源类型参数化，仅要求一次 call 返回类型化共享结果或 core 的统一 Error。LocalScheduler 承载现有本地实现，同时保留返回完整 Run 的 run 入口。目标作为调用参数传入，不增加 GraphCall、LocalGraphCall、绑定目标的代理层或专属子图节点类别。
3. **静态 Graph。** Graph 的参数是 State、业务输出和资源类型。Graph 不保存一次执行的 State、进度或结果。执行体仍由现有节点机制保存和调度，运行状态隔离落实在 Run、State、输入和节点执行记录上；本次不增加节点对象重建或克隆策略。应用可以先创建资源中的固定、一次写入的目标槽位，再构建图，填齐槽位后才开始执行。递归节点在运行时从 Context 解析目标，不要求构图时直接持有对方图。图、节点和初始化闭包不反向持有该资源对象，避免组装形成永久的强引用环；这属于应用的固定目标组装，不增加 core 注册中心。
4. **统一实例化。** 普通静态节点在各 Run 中有自己的执行记录；template 节点通过 Deliver 创建有独立 key 和输入的实例。节点执行内容是否调用另一张图，不改变这些规则。
5. **显式多入口输入。** GraphInput 对应图最终确定的 entries；默认入口为零入度非 template 节点，保留显式指定有入度入口的能力。输入键必须恰好覆盖入口集合。缺失、多余和未知键都在 State 初始化和节点执行之前报错。无数据的入口显式提供空 Input。
6. **输入数据责任。** 框架检查入口集合，具体节点通过既有 Input 读取契约判断是否需要数据及其类型、数量。空 Input 本身合法。不同图间只传显式业务值，入口来源重建为新 Run 的来源，不沿用父节点内部来源记录。内部普通边、Transition payload 与 Deliver payload 的组装语义保持原样。
7. **唯一类型化返回。** 构图时指定唯一非 template 返回节点并核对其声明输出类型。节点无需因为承担返回职责而获得新的执行语义；不强制它必须为零出度节点。返回值提前就绪不结束图。执行、归并、路由或停滞错误均阻止最终结果交付。其他执行步骤成功结束但返回节点没有产出值时，Run 失败并报告返回值缺失。
8. **一致的输出所有权。** 所有节点的 Outcome 值均为可选的业务值 Arc，节点的 Output 仍是业务类型。无业务返回使用单元值；成功但业务值本身可空时，将可空性表达在业务类型内。跨边、返回节点及父子调用直接共享同一个 Arc，不重复包装，不增加输出 Clone 约束。
9. **State 初始化。** 每个新 Run 从头执行图配置的初始化策略。注册函数可以异步读取本次 GraphInput 和不含 State 的执行上下文；初始化完成后才执行节点。未注册时调用 Default，只有该构造路径要求 State 实现 Default。State 类型可以提供关联初始化函数，但 State trait 不增加初始化方法。
10. **资源。** Context 持有强类型资源对象的 Arc，无资源时用单元类型。父子按需显式共享或替换资源，不共享父 State。资源替换保留原有调用身份和深度预算。资源中的外部副作用不获得 State 归并或事务回滚语义；本轮不实现数据库、HTTP、文件服务或资源查找容器。
11. **身份与深度。** 根 ID 由宿主提供，根深度为零且没有父关联。每次子调用自动生成新 ID、记录父 Run ID 和父 NodeKey，深度加一并继承根上限。子调用不能自行放宽预算；超限不执行子初始化或节点。上限为零时允许根图，不允许子调用。
12. **重试。** 父节点每次重新调用 call 都创建新子 ID、独立初始 State 和独立执行记录；同一父节点的重试仍关联同一父 Run 和相同嵌套深度。不接续失败位置，不自动重试，不承诺回滚此前副作用。最大深度约束嵌套，不作为同层重试次数预算；父节点负责自己的重试终止条件。
13. **并发。** 同一 LocalScheduler 实例可以执行父子图，但每次 run 的并发名额独立计算。父节点等待子调用期间仍占据父 Run 名额，子图使用自己的名额。整棵调用树的总并发可能超过单个 Run 的配置值，本次不增加全树并发控制。
14. **Run 与错误边界。** 入口校验或初始化失败直接返回统一 Error，没有完整的带 State 的 Run。进入节点执行后的失败保留在 Run 及其错误列表。call 将这两种结果统一转换为最终 Arc 或调用错误。初始化之前先建立可用于观测的身份，初始化失败仍可关联到本次调用。
15. **稳定错误类别。** 调用错误区分输入不合法、深度超限、初始化失败、执行失败、返回值缺失；保留底层 source 用于诊断。父节点不需要解析子图 NodeId、RunStatus 或错误文本。构图与普通节点错误继续使用 core 既有错误契约。其他接入实现遵守 Scheduler trait 的 core Error 契约，并在边界保留自身错误来源。
16. **父节点处理失败。** 子调用必须报告失败。父节点可以重试、生成降级结果或继续传播错误。明确接受失败并正常返回 Outcome 时，父节点按 Completed 结算，包括它自己的 Delta 和 Directive；不把这种处理解释为 Skipped。是否重试不由错误类型自动决定。
17. **观测。** 使用 tracing 的 Run span；从本次执行开始、初始化之前建立 span，总耗时包含初始化。开始和整图完成使用 DEBUG，初始化或执行失败使用 WARN；记录阶段、受控错误分类及耗时。span 包含经过安全处理的运行身份、父身份、父 NodeKey 和深度。深度拒绝关联到发起调用的父边界，不伪造已执行的子 Run。
18. **观测与停止范围。** 对已开始但被正常丢弃的执行 future，可记录 DEBUG 本地取消事件；这仅说明本地停止观察，不新增 Run 状态或调用结果，不承诺外部停止。未 poll 的 future 不记录开始或取消，正常完成/失败只结算一次，panic 不误报为普通取消。显式 interrupt、Suspend/resume 协议及 InterruptPolicy 均不在本次实施范围。
19. **遥测约束。** 本次不新增调度指标。复用既有宿主 Subscriber 和 Collector 生命周期；core 不初始化 SDK，不读取隐式遥测端点。日志和 span 不包含输入、输出、State 内容、原始配置、凭据或完整错误链。ID 和 NodeKey 限长并编码控制字符；遥测故障、过滤和背压不改变业务结果或触发重试。
20. **公开契约。** 公开类型、完整签名、builder、构造校验、错误来源规则和仅使用根公开 API 的调用示范由配套设计说明给出。本文保留业务决策，不嵌入实施代码。新能力完成前，既有正式规格仍描述当前已实现行为。

## Testing Decisions

测试边界已经用户确认：以公开 LocalScheduler.run 和 Scheduler.call 为主要验收入口，用小型手写 NodeInstance 或 Scheduler fake 形成可控执行行为，沿用现有调度回归、公开 API 及编译期检查。不新增通用 mock 框架、内部事件总线或观测回调 seam。

好测试断言输入、返回、State、节点状态、错误分类、身份、明确的外部调用次数及稳定顺序，不镜像 ready 算法，不用睡眠碰运气决定任务顺序，不依赖私有类型擦除布局或 ID 的字符串格式。测试同步优先复用现有受控节点、通知及屏障方式。

1. **构图与输入入口：** 覆盖唯一返回节点存在性、template 限制和输出类型；自动/显式入口、入口缺失/多余、异构多入口、显式空 Input。非法键不得开始初始化或节点；有效空 Input 是否成功由节点决定。
2. **输出：** 覆盖多个分支汇聚、返回节点提前完成但其他分支失败、归并/路由/停滞导致整图失败、缺失返回值、单元返回及业务可空值。非 Clone 输出可调用和转发；通过公开结果和已知输出句柄验证 Arc 指向同一值，不发生嵌套包装。
3. **初始化：** 覆盖 Default、异步自定义、无 Default 的 State、初始化读取本次输入和资源、初始化失败以及初始化完成前零节点执行。每次调用和重试独立初始化；初始化函数不能取得父 State。
4. **隔离与实例化：** 覆盖父子不同 State、同一图多次/并发执行、内部 NodeId 和实例 key 可在不同 Run 重用、父来源不泄漏、template 子调用与普通 template 实例相同的 fan-out/join 行为。
5. **身份与深度：** 验证根/子/孙身份、父 NodeKey、零上限、恰好达到上限、下一层拒绝、同层重试深度不增长以及资源替换不改变调用身份。通过应用资源中的固定一次写入槽位，分别组装自递归和 A/B 相互调用；在上限为二时断言实际开始执行的深度只有零、一、二，第三层在创建子执行前被拒绝。直接发起超限调用的节点收到 DepthExceeded；向外传播后，外层已开始的图按执行失败结算，不错误要求根结果仍为顶层 DepthExceeded。验收还检查释放运行及资源后图定义可释放；不要求产品新增注册中心。
6. **并发：** 同一个 LocalScheduler、并发上限一时，父等待子仍能完成；受控节点证明每个 Run 各自遵守名额限制。继续验证固定 wave、稳定结算顺序、Sweep、Transition、Deliver 和写入冲突的既有行为。
7. **错误与重试：** 分别验证五类调用错误、source 保留、启动失败直接 Err、运行失败保留完整 Run 错误列表、父显式处理失败后 Completed、未处理错误向上传播、重试新身份新 State，以及外部副作用不会自动撤销。不自动推导重试策略。
8. **调度替换：** 用一个不执行本地图、也不构造本地 Run 的小型 Scheduler fake 验证父节点只依赖 trait、输入和结果；不为测试实现远程 agent 或网络服务。
9. **观测：** 验证开始/完成/失败的级别与阶段、身份关联、总耗时包含初始化、未 poll 零事件、正常 drop 的本地取消和安全字段。补充测试外层的 caught-unwind 验收：初始化 panic 穿过 Run 观测 guard 时，不产生普通 cancel 或伪造完成/失败；节点 panic 由已有任务边界转换为执行错误时，Run 恰好记录一次失败，不额外记录 cancel 或完成。嵌套调用的初始化 panic 同样按各自 Run 身份区分未正常返回的子执行与捕获任务失败的外层执行。分别核对正常完成、预期 Err 和 panic 后的清理均不重复结算。捕获 unwind 仅用于测试核对事件，不给产品增加 panic 捕获、恢复或中断协议。复用 Collector 既有故障与输出背压测试模式，证明未初始化、遥测失败和背压不改变调用行为。
10. **公开 API 与编译约束：** 延续现有外部使用者构图和只读检查样例，确认类型、builder 和错误均根导出可达；复用 trybuild 的成功/失败夹具模式，验证自定义初始化不要求 Default、输出不要求 Clone，以及实际需要的 Send/Sync 约束。
11. **验证组织：** 业务 UT 保留在源码测试模块，外部调用样例和编译期验证作为已有边界的补充。核心功能不访问数据库或外部服务。实现阶段遵循仓库格式、离线检查、clippy、无数据库 UT 和依赖检查约定，并单独执行受影响的公开 API、编译和 CLI 验收目标；本次文档提交仅检查内容、空白及文件结尾。
